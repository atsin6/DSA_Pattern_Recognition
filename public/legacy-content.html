Sliding Window
Variable or fixed-size window moving over array/string
📡Recognition Signals
subarray / substring contiguous elements longest / shortest window k distinct characters at most / at least k no repeating characters max sum of size k minimum window containing all
⚖️When to Use / Avoid
✓ Use When
  • Contiguous subarray/substring required
  • Fixed or variable window size
  • Linear scan is enough
  • Frequency constraint within window
✗ Avoid When
  • Non-contiguous elements needed
  • Elements can be reused from anywhere
  • Need all combinations (use backtracking)
  • Array is unsorted and search is needed

Two Pointers
Two indices moving toward or away from each other
📡Recognition Signals
sorted array pair / triplet with target sum palindrome check remove duplicates in-place two sorted arrays merge container with most water partition array
⚖️When to Use / Avoid
✓ Use When
  • Array is sorted (or can be sorted)
  • Looking for a pair meeting a condition
  • In-place modification needed
  • Comparing from both ends
✗ Avoid When
  • Array is unsorted and sorting changes answer
  • Non-contiguous elements with complex condition
  • Window has frequency/map constraints (use sliding window)

Prefix Sum
Precompute cumulative sums for O(1) range queries
📡Recognition Signals
range sum query subarray sum = k number of subarrays with sum multiple queries on same array 2D grid sum queries contiguous subarray count
⚖️When to Use / Avoid
✓ Use When
  • Multiple range sum queries needed
  • Count of subarrays with exact sum
  • Immutable array with repeated queries
  • Difference arrays for range updates
✗ Avoid When
  • Array is modified frequently (use Fenwick tree)
  • Window size is fixed (sliding window is simpler)
  • You only need one range sum

Hashing
HashMap / HashSet for O(1) lookups, counting, grouping
📡Recognition Signals
two sum / pair with target frequency count duplicate detection group / categorize elements anagram check first occurrence / index map O(1) lookup needed
⚖️When to Use / Avoid
✓ Use When
  • Need O(1) average lookup
  • Counting occurrences of elements
  • Grouping elements by a key
  • Checking membership quickly
✗ Avoid When
  • Order/range matters (use sorted array)
  • Memory is very limited
  • Hash collisions cause correctness issues

Binary Search
Eliminate half the search space each iteration — O(log n)
📡Recognition Signals
sorted array find target in sorted minimize / maximize answer search on answer space rotated sorted array find peak / boundary kth smallest/largest in matrix feasibility check monotone
⚖️When to Use / Avoid
✓ Use When
  • Array or search space is sorted/monotone
  • Answer space is numeric and bounded
  • "Can we achieve X with capacity Y?" pattern
  • O(log n) required over O(n)
✗ Avoid When
  • Array is unsorted (unless you can binary search answer)
  • Elements don't have monotone property
  • Need to find all occurrences (use bounds)

Recursion / Backtracking
Explore all possibilities, prune invalid branches early
📡Recognition Signals
all permutations / combinations all subsets / power set generate all valid strings satisfy constraints N-Queens, Sudoku word search on grid partition into groups
⚖️When to Use / Avoid
✓ Use When
  • Enumerate all valid configurations
  • Decision at each step (include/exclude)
  • Constraint satisfaction problem
  • Small input (n ≤ 20)
✗ Avoid When
  • Need only one optimal answer (use DP/Greedy)
  • Input is large (exponential blowup)
  • No pruning possible (too slow)

Greedy
Make locally optimal choice at each step — no reconsideration
📡Recognition Signals
interval scheduling / merging minimum cost / maximum profit activity selection task scheduling gas station / jump game assign to minimize conflicts
⚖️When to Use / Avoid
✓ Use When
  • Local optimal leads to global optimal (provable)
  • Interval problems (sort by end time)
  • Fractional knapsack
  • Can prove greedy choice property
✗ Avoid When
  • Choices affect future in non-obvious ways
  • 0/1 Knapsack (use DP)
  • Problem has overlapping subproblems

Dynamic Programming
Memoize overlapping subproblems, build bottom-up or top-down
📡Recognition Signals
overlapping subproblems optimal substructure count ways to reach min/max cost to reach end 0/1 knapsack longest increasing subsequence edit distance / string match partition array optimally
⚖️When to Use / Avoid
✓ Use When
  • Recursive solution has repeated subproblems
  • Need count of ways or min/max paths
  • State can be described with few variables
  • Greedy fails (choices affect future)
✗ Avoid When
  • No overlapping subproblems (use divide & conquer)
  • Greedy provably works (simpler)
  • State space is exponentially large

Cross-Pattern Comparison
Choose the right pattern when two seem applicable
Sliding Window vs Two Pointers
Sliding Window
  • Contiguous subarray / substring
  • Frequency / count constraint within window
  • Window expands/shrinks based on HashMap state
  • Array can be unsorted
Two Pointers
  • Pair / triplet sum with target
  • Array must be sorted (or sorting valid)
  • Pointers move toward each other (not same direction)
  • In-place modification / partition
Rule: If you need a HashMap inside the loop → Sliding Window. If sorted + pair search → Two Pointers.
BFS vs DFS
BFS
  • Shortest path in unweighted graph
  • Level-by-level processing needed
  • Minimum steps / hops
  • Uses Queue — iterative naturally
DFS
  • Connected components / flood fill
  • Cycle detection
  • Path existence / backtracking
  • Uses Stack / recursion naturally
Rule: Need shortest path or minimum steps → BFS. Need all paths, cycle, or connectivity → DFS.
Greedy vs Dynamic Programming
Greedy
  • Local optimal = global optimal (provable)
  • No backtracking needed
  • Interval / scheduling problems
  • O(n log n) after sort
Dynamic Programming
  • Choices affect future states
  • Overlapping subproblems
  • Count of ways, not just yes/no
  • 0/1 decisions (include or skip)
Rule: Try Greedy first. If a counterexample breaks it → use DP. 0/1 Knapsack always needs DP.
Heap vs Sorting
Heap (Priority Queue)
  • Data arrives dynamically (stream)
  • Repeatedly need current min/max
  • k-th element with online updates
  • O(n log k) for top-k problems
Sorting
  • All data available upfront
  • Need full order once
  • Simpler code, same O(n log n)
  • Random access after sorting needed
Rule: Static data + single sort pass → Sort. Dynamic/streaming data + repeated min/max → Heap.
Prefix Sum vs Sliding Window
Prefix Sum
  • Count subarrays with exact sum = k
  • Many random range queries
  • Negative numbers in array
  • Combines with HashMap for count
Sliding Window
  • Longest/shortest window with constraint
  • All numbers non-negative (monotone sum)
  • Fixed window size
  • Window shrinks/grows dynamically
Rule: Contains negative numbers + exact sum count → Prefix Sum. Non-negative + max/min length window → Sliding Window.
